*MERN Stack Assignment – E-Commerce Application*
Objective
Build a complete MERN Stack E-Commerce Application using the MERN Stack with Authentication, Role-Based Authorization, Product Management, Shopping Cart, Wishlist, Checkout, and Order Management.

User Roles
*1. Admin*

The Admin manages the complete application.
Admin Dashboard

Display the following statistics:
	•	Total Users
	•	Total Customers
	•	Total Admins
	•	Total Products
	•	Total Orders
	•	Total Revenue (Optional)
	•	Recent Orders (Optional)
	•	Recent Registered Users (Optional)

*User Management*
Admin should be able to:
	•	View all registered users
	•	View user details
	◦	Name
	◦	Email
	◦	Role
	◦	Registration Date
	•	Display total registered users
	•	(Optional) Change user role
	•	(Optional) Delete user

Product Management
Admin should be able to:
	•	Add Product
	•	Update Product
	•	Delete Product
	•	View All Products

Each product should contain:
	•	Product Image
	•	Product Name
	•	Description
	•	Category
	•	Price
	•	Stock Quantity
	•	Created Date

Order Management
Admin should be able to:
	•	View all orders
	•	View customer details
	•	View ordered products
	•	View quantities
	•	View total amount
	•	View order date
	•	Update order status (Optional)

*2. Customer*
Authentication
	•	Register
	•	Login
	•	Logout

Customer Dashboard
Customer should be able to view:
	•	Total Orders
	•	Wishlist Items
	•	My Orders
	•	Profile (Optional)

Customer must only be able to view their own orders.

Public Pages
	•	Home
	•	Products
	•	Product Details
	•	Login
	•	Register

Home Page
Display all products added by the admin.
Each product card should display:
	•	Product Image
	•	Product Name
	•	Category
	•	Price
	•	Short Description
	•	Add to Cart
	•	Favorite Button
	•	View Details

Whenever the admin adds a new product, it should automatically appear on the frontend.

Product Details Page
Display:
	•	Large Product Image
	•	Product Name
	•	Price
	•	Description
	•	Category
	•	Stock
	•	Add to Cart
	•	Favorite Button

Shopping Cart
Users should be able to:
	•	Add products
	•	Remove products
	•	Increase quantity
	•	Decrease quantity
	•	View subtotal
	•	View total amount
	•	View total items

Wishlist (Favorites)
Users should be able to:
	•	Add products to Favorites
	•	Remove products from Favorites
	•	View all favorite products

Checkout Flow
When the user clicks the Checkout button, the application should always open the Checkout Page.
If the User is Logged In
	•	Display the complete checkout form.
	•	Allow the user to review the cart and place the order.
If the User is Not Logged In
	•	Do not redirect to the Login page.
	•	Stay on the Checkout page.
	•	At the top of the page, display a login section containing:
	◦	Email
	◦	Password
	◦	Login Button
	•	Display the checkout form below the login section.
	•	Keep the checkout form disabled until login is successful.
	•	After successful login:
	◦	Hide the login section.
	◦	Enable the checkout form.
	◦	Preserve the shopping cart.
	◦	Continue the checkout process without leaving the page.

Checkout Page
Login Section (Only for Unauthenticated Users)
	•	Email
	•	Password
	•	Login Button
This section should automatically disappear after successful login.
Checkout Form
	•	Full Name
	•	Email (Auto-filled after login if available)
	•	Phone Number
	•	Shipping Address
	•	City
	•	Postal Code (Optional)
	•	Order Notes (Optional)
Order Summary
	•	Ordered Products
	•	Quantity
	•	Individual Price
	•	Subtotal
	•	Total Amount
Place Order
Clicking Place Order should:
	•	Validate checkout information
	•	Save the order in MongoDB
	•	Associate the order with the logged-in customer
	•	Clear the shopping cart
	•	Redirect to My Orders or Order Success page

My Orders
Customers should only be able to view their own orders.
Each order should display:
	•	Order ID
	•	Ordered Products
	•	Quantity
	•	Total Amount
	•	Order Date
	•	Order Status (Optional)

Authentication & Authorization
Implement:
	•	JWT Authentication
	•	bcrypt Password Hashing
	•	Protected Routes
	•	Role-Based Authorization
Only Admin can access Admin routes.
Customers must not be able to access Admin pages.
